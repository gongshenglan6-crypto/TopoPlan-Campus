# 赛事提交清单

依据参赛者提供的作品提交要求整理。PDF 不超过 30 页；演示视频由参赛者另行制作。

| 要求 | 当前状态 | 提交前动作 |
| --- | --- | --- |
| GitHub / Gitee 仓库 | 本地源码仓库及 bundle 已提供 | 上传并设为 Public 或授予评审权限 |
| 注释与代码规范 | 保留模块结构、注释与测试 | 团队复核，避免把构建产物提交入库 |
| README 与环境配置 | 已提供，团队成员与分工已填写 | 上传后补充真实仓库地址 |
| Git 记录 | 有本次整理的真实记录 | 若有原始历史，合并保留；不得伪造 |
| 技术文档 PDF | 已提供 | 检查作品名称、团队信息及最终版本 |
| 演示视频 | 按用户要求未制作 | 自行录制 5-8 分钟 MP4，至少 1080p，普通话讲解可配字幕 |
| 在线演示 | 可选，未部署 | 如参加加分项，提供公网地址和评审账号 |
| 密钥隔离 | 已提供无密钥源码及环境模板 | 只填写本机 .env，勿推送个人数据库与日志 |
| 截止前官网提交 | 由参赛者完成 | 以赛事官网时间和最新要求为准 |

## 上传现有本地仓库
在项目根目录将真实成员信息填写并提交后，设置自己的 GitHub/Gitee 远程地址，推送 main 分支。请保留现有 .git，不要仅上传散落源码而丢失记录。如平台仅允许网页上传，需确认能否保留 Git 历史；建议使用 Git 客户端推送。

## bundle 恢复
将 TopoPlan-history.bundle 与其他材料分开存放。在终端使用 git clone TopoPlan-history.bundle TopoPlan 恢复仓库；恢复后 npm ci 和 Maven 会重新获取依赖。

## 重要提交边界
本地整理不能替代远程仓库可访问性、视频提交或赛事官网操作。原始开发历史在提供的目录中不可用，本包没有伪造历史。团队名称、成员及分工安排已根据参赛者信息填写，正式提交前应由团队共同复核。
