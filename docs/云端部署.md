# 云端部署

## 结构

根目录 Dockerfile 分三阶段构建：Node 构建 Vue 静态资源；Maven 将静态资源与 Java 后端打入同一个 JAR；Java 21 运行该 JAR。网页与 API 同源，避免跨域登录 Cookie 与流式请求问题。SpaController 只转发已知页面路由，API 和缺失资源不被 HTML 兜底覆盖。

## 已有云服务器部署

根目录 compose.yaml 提供独立 MySQL、网站和可选 Caddy HTTPS 服务。数据库不对公网开放，网站默认仅在服务器 127.0.0.1:8188 暴露，方便已有 Nginx 等反向代理接入。首次部署前应检查服务器已有站点、端口和资源，使用独立目录与卷，避免覆盖原系统。

复制 .env.server.example 为服务器本机 .env，填写随机数据库密码、JWT、加密主密钥和管理员初始密码。已有反向代理时运行 docker compose up -d --build mysql app，再为实际域名配置代理到 127.0.0.1:8188。空服务器且域名已正确解析时，可运行 docker compose --profile https up -d --build，由 Caddy 提供 HTTPS。确认使用 HTTPS 后保持 Secure Cookie 启用。服务器 .env 不提交仓库。

## Railway 配置

1. 创建演示项目及 MySQL 服务，数据库保持私网访问。
2. 从根目录 Dockerfile 部署 TopoPlan，或由 Railway CLI 上传源码部署。
3. 网站服务挂载持久卷到 /data，用于上传资源与日志。
4. 将 MySQL 服务的 MYSQLHOST、MYSQLPORT、MYSQLDATABASE、MYSQLUSER、MYSQLPASSWORD 连接信息引用到网站环境变量。JDBC URL 采用 jdbc:mysql://主机:端口/数据库?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true；私网连接的 TLS 参数按数据库配置确定。
5. 设置 TOPO_DB_USERNAME、TOPO_DB_PASSWORD、TOPO_CONFIG_ENCRYPTION_KEY、TOPO_JWT_SECRET、TOPO_ADMIN_PASSWORD。密钥由部署时生成并私下保存，不提交源码。首次管理员用户名为 admin。
6. 由平台生成公开 HTTPS 域名，端口使用平台 PORT。开启 Secure Cookie，并通过代理头恢复原始 HTTPS 协议。
7. 新演示环境不导入原始用户业务数据库。AI 模型 Key 由管理员在已部署系统中自行配置；没有有效模型渠道时，不宣称 AI 功能已可用。

## 状态核对

railway.json 指定 Docker 构建、根页面健康检查和失败重启。Dockerfile 默认监听 0.0.0.0，平台可访问网站；本地开发默认仍绑定 127.0.0.1。新增页面刷新与 API 不被兜底覆盖两项测试后，后端 57 项测试通过。

在新公网环境中检查首页、管理员登录、普通用户项目创建与保存、上传资源持久化、页面刷新、AI 原生 SSE 和评审账号访问。只有实际部署和公网验收成功后，才将真实域名写入提交材料。

Railway 试用存在额度、时间、内存和网络限制；是否能够覆盖评审期以账户状态为准，不作永久免费或持续在线承诺。付费升级需账户持有人确认。
